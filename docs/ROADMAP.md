# 实施路线与验收

## 阶段 0 · 正式工程结构（本次建立）

- 保留最早原型于 \`legacy/noir-desk.html\`，从中提取 CSS、城市图层、节点、时钟与原始剧情数据。
- 原生 ESM 项目，数据、规则与界面分层，不依赖大型框架。Node 自带测试运行器，提供本地静态服务器。
- \`src/engine/game.js\` 不访问 DOM、网络或本地存储。规则独立于内容，支持注入随机源做确定性测试。
- \`src/data/content.js\` 提供统一内容契约；新增人物/行动时无需改核心概率与日结算。
- **完成标准**：\`npm run check\` 通过；从浏览器打开 \`npm run dev\` 的页面，可点击地图、选择卡牌、落子和收工。

## 阶段 1 · 七天真实可玩性测试（当前主要任务）

- 让主角在工资、查案、阿砖、风险、休息上产生相互冲突的行动选择。
- 阿砖不等玩家：工头合同压力每天推进；周五面是具体日期事件，能够在结局中被引用。
- 调整价格、行动力、风险、时钟，目标不是数值平衡而是玩家产生犹豫和遗憾。
- **验收**：3次完整的七天试玩；每次记录两次真正困难的选择；没有无限刷钱、无代价最优解、卡死、没有反馈的机械重复。

## 阶段 2 · 人物作为独立他者

- 为人物建立日程、偏好、拒绝条件、同伴可用时间与具体反应。
- 让事实成为下一次见面的条件；不采用可存取的好感度账户。
- 每个核心人物至少一段非玩家干预也能独立完成的发展。
- **验收**：同样七天、两种不同参与方式，人物反应和结局能以生活事实解释，而不是人情点数。

## 阶段 3 · 事件和叙事

- 事件队列、触发条件、事件优先级、晚间后果；加强四段文本合成，保留手写专属句子。
- 街头小事、人物线、城市大事件共用节点、时钟、牌和事实。
- **验收**：事件不反复误触发；数值与叙事一致；同一行动用不同人手会产生有意义区别。

## 阶段 4 · 限时契约和主线

- 契约复用同一引擎但采用局部预算、局部地图和永久结果。
- 延展夜莺、兄弟与港口公司的主线，使之前的生活经历在共同危机中兑现。
- **验收**：失败也产生可继续玩的后果；结局有角色差异、引用具体玩家行为。

## 结构上的约束

- 先保证 \`src/engine\` 规则稳定、可测试，再扩内容；新增内容写在 \`src/data\`，不要把剧情条件塞进 DOM。
- 每个公开阶段都应有可启动版本，不允许把整个项目停留在一长串规划文档。
- 默认不添加新的抽象资源、道德计量、独立关系货币或自由合成机制。
- 不把「系统完整」误解为「第一版功能全开」：接口与边界完整，内容和机制按体验验证逐步生长。
